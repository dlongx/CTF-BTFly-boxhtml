工具包使用说明

这份说明书面向日常使用者：告诉你这套工具包能解决什么问题、怎么导入、怎么让 AI 在解题时真正用上它， 以及遇到问题时怎么自己修。全文不需要任何命令基础，照着步骤点就行。

✓
先看这一句 工具包安装好后，不需要你手动选包。BTFly 会按题目类型自动挂载合适的工具包： Web/杂项用「基础包」，逆向/Pwn 用「基础包 + 逆向增强包」。

这套工具包能做什么

它把 CTF 比赛里最常用的一批分析工具打包成「即插即用」的形式：装进 BTFly 之后， AI 在解题时会像调用内置功能一样调用它们，而不是自己去网上找脚本、装依赖。

替你做粗活

一键看二进制结构、加固项、字符串、反汇编片段，不用记 readelf、objdump 那串参数。

少踩环境的坑

Python、Ghidra、nuclei、OCR 全部内置，不联网也能跑，不会出现“我这儿缺个库”。

省下你的时间

实测同一道 PyInstaller 逆向题：有专用工具包 77 秒解完，没有的话要 116 秒（还得联网装包）。

结果可复现

每次工具调用都会记录参数与输出，写出来的解题过程（WP）能被人照着复现。

工具包里有什么

工具包按用途分成两种「组合包」，组合包本身不含大文件，只是把下面这些独立工具包按需串起来：

组合包装了什么什么时候用工具数量
CTF Full Toolset
基础包		 ELF 侦察、Pwn 辅助、密码学预检、取证扫描、Web 指纹、nuclei、OCR、Python 逆向工具 Web / 杂项 / 密码 / 取证 / 大部分逆向 15 个
CTF Full + Reversing
逆向增强包		 基础包全部内容 + Ghidra 反编译（约 600 MB） 逆向 / Pwn（需要看伪代码时） 16 个
i
为什么分两个包 逆向增强包里的 Ghidra 体积很大（约 600 MB），装多了会让每次开题变慢。所以只在逆向/Pwn 题里才挂载它， 其它题型用基础包，既快又够用。

用之前先确认

  • BTFly 主程序为 2.9.x（当前发行版 2.9.5）；工具包清单格式为 schemaVersion: 1，跨 2.9.x 小版本通用。
  • 磁盘至少留出 1.5 GB 空间（逆向增强包解压后约 1 GB）。
  • 应用里能看到「工具包」设置页（设置 → 工具包）。

方式一：界面按钮导入（推荐给普通包）

  1. 打开工具包页面 进入「设置 → 工具包」，页面顶部能看到「导入 .ctfpack」按钮。
  2. 选择文件 点击按钮，选中你下载的 .ctfpack 文件。文件名形如 ctfagent.ctf-full-2.9.1.ctfpack。
  3. 确认未签名提示 这些包由本地构建，不是商店签名包，会弹出「确认安装未受信任 Tool Pack？」。 勾选/点击「我已检查，继续安装」即可。
  4. 等待安装完成 小包（几十 MB）几秒完成；逆向增强包（约 600 MB）需要 20 秒到 1 分钟，请勿关闭窗口。
  5. 确认已启用 安装完成后，包默认是「已安装但未启用」还是「已启用」取决于版本，稳妥起见在列表里确认「启用包」是打开状态。
!
大包建议用「按路径导入」 超过约 200 MB 的包（尤其是逆向增强包），用下面的路径方式导入更稳，不会让界面卡住。

方式二：按路径导入（大包专用，更稳）

如果你的包很大，或者界面导入一直转圈，用这个方式：文件不经过浏览器，由后台直接读取。

  1. 复制文件完整路径 在文件管理器里右键 .ctfpack 文件 → 属性 → 复制「位置 + 文件名」， 例如 D:\packs\ctfagent.ctf-full-re-2.9.1.ctfpack。
  2. 粘贴到「从本地路径导入」 工具包页面有一行「从本地路径导入（大包推荐）」的输入框，把路径粘贴进去。
  3. 点击「从路径导入」 同样会弹未签名确认，确认后等待完成即可。
i
路径要求 必须是绝对路径且以 .ctfpack 结尾，例如 D:\packs\xxx.ctfpack。相对路径会被拒绝并提示正确示例。
!

命令行/脚本导入时的编码要求（重要）

如果你不是用界面、而是用脚本或命令行走 POST /api/toolpacks/import-path 导入，请求体的 JSON 必须是 UTF-8 编码。当路径包含中文（例如 D:\packs\需要导入\...）时，用系统默认的 GBK/ANSI 写出的 JSON 会让后台收到乱码路径，报「The system cannot find the path specified」。

正确写法示例：

python -c "import json,sys; sys.stdout.buffer.write(json.dumps({'path': r'D:\你的路径\包.ctfpack'}, ensure_ascii=False).encode('utf-8'))"

或指定 PYTHONIOENCODING=utf-8；PowerShell 用 Out-File -Encoding utf8。

另外，未签名工具包需要请求头 X-CTFAgent-Untrusted-Code-Consent: install-this-tool-pack，否则会返回 TOOLPACK_UNTRUSTED_CONSENT_REQUIRED。

导入后怎么确认成功

  • 工具包列表里出现对应条目，且「启用包」为开启状态。
  • 条目下方的工具列表，每个工具右侧的「启用」开关都是打开状态。
  • 右上角「已安装 N 个包 · M 个工具」计数增加。
  • 最关键的一步：去「设置 → MCP」页，确认能看到 toolpacks（Tool Pack Bridge）并且是启用状态。
✓
导入后什么时候生效 2.9.3.5 及以后：导入完成后最多等 30 秒，AI 的工具列表里就会出现新工具，不需要重启应用。
2.9.3.4 及以前：必须完全退出并重新打开应用。
i
已经跑起来的任务看不到新工具 MCP 服务绑定是在创建任务时冻结的。导入新包后请新建一道题，旧任务不会热更新工具列表。

创建题目时怎么选工具包

不需要你选。BTFly 内部只保留一个「载体包」负责把沙箱跑起来（默认 ctfagent.windows-base）， 而所有已安装工具包的工具都通过 MCP 服务统一暴露给 AI，AI 自己按题型挑。

角色由谁承担说明
沙箱载体（必需）ctfagent.windows-base随发行版内置，装完即可建题
工具来源（按需）其余全部工具包通过 MCP 暴露，导入即可用，AI 自主调用
目录视图ctfagent.ctf-full内置，提供一个 list-packs 工具，让 AI 看到有哪些包
✓
「一个包坏掉导致建不了题」已不再发生 载体包只影响沙箱能否启动；其余工具包即使缺失、损坏或依赖不全，也只会让 AI 少几个工具，任务照常能起。

让 AI 使用工具

所有工具包工具都经由 MCP 调用。AI 看到的工具名形如 packs__ctfagent_media_ocr_ocr（packs__ 前缀 + 包名 + 工具名）。 你不需要记这些名字，只要说清楚要做什么，AI 会自己挑。

想让它一定优先用工具、而不是自己敲命令，可以这样写：

请优先使用已注册的工具（名字以 packs__ 开头），不要用 bash 直接拼脚本命令行。
需要看图 / 读文字时优先调用 packs__ctfagent_media_ocr_ocr（OCR）；
需要分析二进制时优先调用 packs__ctfagent_elf_recon_*。
先看附件类型，再选合适的工具分析，最后给出结论与依据。
i
工具在宿主侧执行，工作目录是本题 workspace 工具内部按相对路径访问附件与产物（例如 attachments/a.png、artifacts/out.txt）， 绝对路径也能用。工具会自己校验参数，漏了必填项会直接返回参数说明，AI 会照着重试。
!
MCP 工具在宿主机执行，不在 AppContainer 内 这是刻意的设计取舍：工具用宿主权限运行，因此能读写你用户目录下的文件。 请只导入你自己构建或审核过的 .ctfpack。沙箱隔离只约束 AI 的内置工具（bash / 读写文件）。

按题型的使用套路

逆向：先看是什么，再解包，最后看字节码

  1. 判断文件类型pe-summary 看是不是 PE / PyInstaller / UPX 打包。
  2. 解包如果是 PyInstaller，用 pyinstxtractor 解出 .pyc。
  3. 反汇编用 pyc-disasm 看字节码；需要伪代码时用 decompile（Ghidra）。
  4. 写解法让 AI 把还原出的逻辑写成 solve.py，并验证目标串。

Pwn：先摸底，再找 gadget

  1. 看二进制elf-summary 一次性拿到架构、PIE/RELRO/NX/Canary。
  2. 看字符串与符号strings 找提示与后门函数名。
  3. 找 gadgetgadget-summary 按约束分类，不用翻几万行。
  4. 写 exp让 AI 用内置 pwntools 写脚本，先本地跑通再打远端。

Web：先指纹，再扫面

  1. 单请求指纹http-baseline 看状态码、关键安全头、标题、长度。
  2. 低噪扫描nuclei-scan 默认限速 3 请求/秒、超时 5 秒，不会把靶机打挂。
  3. 人工判断扫描只给线索，是否深入由你决定。

密码：先排掉低级错误

  1. RSA 预检rsa-quickcheck 检查 e 太小、共模、小素数等常见陷阱。
  2. 再用 z3复杂约束交给内置 z3 求解。

取证与杂项

  1. 扫规则yara 用内置 CTF 规则找 flag 形状、webshell、base64 块。
  2. 看图片文字ocr 识别截图/扫描件里的文字。
  3. 看十六进制hexdump 按偏移切片，不会把整个文件倒进上下文。

工具清单 · 侦察与逆向

packs__ctfagent_elf_recon__elf_summary只读
把 ELF 文件的架构、位数、类型、入口、加固项（PIE/RELRO/NX/Canary）、依赖库、关键符号、节表一次性变成 JSON。
参数：path（文件路径）、maxSections（默认 40）、symbols（默认 60）
packs__ctfagent_elf_recon__disasm只读
从入口点开始的反汇编片段，默认 120 条，支持 x86 / x86-64 / ARM / AArch64。
参数：path、count、architecture
packs__ctfagent_elf_recon__strings只读
按信息量排序的可打印字符串（URL/路径/flag 形状/哈希/base64），只回前 N 条。
参数：path、minLength（默认 6）、top（默认 60）
packs__ctfagent_elf_recon__hexdump只读
按偏移与长度切片十六进制，带 ASCII 对照。看文件头、结构体最方便。
参数：path、offset、length（默认 256）
packs__ctfagent_py_rev__pe_summary离线内置
PE 摘要：位数、入口、节表、导入 DLL 数量，并提示是否 PyInstaller / .NET / UPX 打包。
参数：path
packs__ctfagent_py_rev__pyinstxtractor离线内置
解包 PyInstaller 程序，产物在同级 <文件名>_extracted/，里面能找到 .pyc。
参数：path
packs__ctfagent_py_rev__pyc_disasm离线内置
反汇编 .pyc，跨 Python 版本（内置 xdis），默认 400 行、可调。
参数：path、maxLines
packs__ctfagent_re_ghidra__decompile重型 · 仅逆向包
用 Ghidra 做无界面分析，导出前 N 个函数的伪 C（默认 40）。首次分析大文件需要几分钟。
参数：path、maxFunctions、analysisTimeoutSeconds

工具清单 · Pwn 与 Crypto

packs__ctfagent_pwn_kit__gadget_summary只读
把 ROPgadget 的海量输出按约束聚类（pop rdi/rsi/rdx/rax、syscall、写内存、栈迁移等），每类只给几条。
参数：path、maxPerCategory（默认 3）、timeout
packs__ctfagent_crypto_lattice__rsa_quickcheck离线
RSA 攻击面预检：素模数、e=1/e=3 无填充、共模、Wiener 小 d、小素数因子。只给候选，不做大规模分解。
参数：n、e、c、n2

工具清单 · 取证与 Web

packs__ctfagent_forensics_scan__yara离线
用内置 CTF 规则扫描文件（flag 形状、PHP webshell、base64 大块、PowerShell 下载原语），返回命中位置。
参数：path、maxMatches
packs__ctfagent_web_recon__http-baseline联网
单请求 HTTP 指纹：状态码、关键安全头、页面标题、响应长度。不做任何爆破。
参数：url、method（默认 GET）
packs__ctfagent_web_nuclei__nuclei-scan联网 · 限速
nuclei 低噪模板扫描，默认 3 请求/秒、5 秒超时，只回 JSONL 命中行。
参数：url、rateLimit、timeoutSeconds

工具清单 · 媒体与重型工具

packs__ctfagent_media_ocr__ocr离线
图片文字识别（默认英文+简体中文），适合截图、扫描件、验证码类图片。
参数：path、language、psm
packs__ctfagent_ctf_full__list-packs诊断
列出本任务实际挂载了哪些工具包、每个包有哪些工具。怀疑“工具没生效”时先跑它。
参数：无

工具清单 · 远程桌面与图像链路（v2.9.1 新增）

这一组工具面向「只暴露一个静默 TCP 端口的自助终端」这类题目，覆盖从协议识别到键鼠注入的完整链路。全部为随包分发的离线件，除标注「网络」的工具外不访问外网。

packs__ctfagent_remote_vnc__vnc_probe网络
识别静默端口是否为 RFB/VNC：主动发送 RFB 003.008\n（服务端在收到客户端版本前不会说话），返回协议版本、安全类型列表、是否需要口令。
参数：mode（固定 probe）、host、port、timeout
packs__ctfagent_remote_vnc__vnc_shot网络
认证后抓取全屏或指定区域的 PNG 截图。强制 32bpp 真彩色 + Raw 编码，无需任何解压库。
参数：mode（固定 shot）、host、port、password（无认证传 -）、out、crop（x,y,w,h 或 -）、timeout
packs__ctfagent_remote_vnc__vnc_act网络
在一次会话内注入鼠标与键盘事件，并可保存最终截图。动作用分号分隔的 DSL 表达。
参数：mode（固定 act）、host、port、password、actions、out、timeout
动作语法：click:x,y、move:x,y、key:Return、keydown:Control_L、keyup:Control_L、type:文本、paste:文本、wait:秒、shot:路径[,x,y,w,h]
packs__ctfagent_screen__screen_triage离线
无显示器时的截图分析：ascii 生成亮度字符画看布局、diff 用像素差判断界面是否真的变化、crop 裁剪放大、qr 二维码二值化预处理、info 基础信息。
参数：mode、image、image2（仅 diff 用）、params、out
packs__ctfagent_qr__qr_decode离线
用随包内置的 zxing-cpp 解码二维码/条码，返回文本、格式、字节 hex、有效性与四角坐标。不需要 zbar、pyzbar 或任何系统安装。
参数：mode（固定 decode）、image、out（传 -）、text（传 -）
packs__ctfagent_qr__qr_generate离线
把任意负载渲染成二维码 PNG，用于自检、候选种子比对与写进 WRITEUP 的可扫码产物。
参数：mode（固定 generate）、image（传 -）、out、text
packs__ctfagent_totp__totp_generate离线
RFC 6238 动态口令生成，支持计数器偏移扫描。靶机时钟常与本地不同步，建议一次取 0,-1,1,-2,2 逐个试。
参数：secret、digits（6/7/8）、period（通常 30）、algorithm（sha1/sha256/sha512）、offsets、timestamp（- 表示现在）
packs__ctfagent_net_probe__net_greet网络
按协议发主动问候并读响应：RFB、SMTP、POP3、IMAP、Redis、Memcached、HTTP 为主动问候；FTP、SSH、MySQL、Telnet 为被动等 banner。
参数：host、port、protocols（auto 或 rfb,redis 这类子集）、timeout
packs__ctfagent_net_probe__net_reach网络
探测超时后先跑它：区分「跨网段死路」「有路由但被过滤」「对端 RST（端口关闭）」「已监听」，并返回本机 IP、是否同 /24、沙箱注入的代理变量。一次调用替代 ipconfig/route/ping 四五步。
参数：host、port、timeout

工具包怎么交付（重要）

搞清「哪些随版本内置、哪些要手动导入」，可以避免「明明有包却用不上」和「重复导入」两种常见困惑。

一、随版本内置 —— 开箱即用，不需要你导入
位置：发行包解压目录下的 ToolPacks\。
行为：首次启动应用时，daemon 会自动安装并启用其中的包（ensureBundledToolPacks），无需任何手动操作。
当前内置内容：只有一个「工具包目录」元包 ctfagent.ctf-full。它不含实际工具，只提供一个 list-packs 工具，用来告诉解题 Agent 当前有哪些工具包可用。它不依赖任何其它包，因此不会因为缺依赖装不上。
注意：内置包不需要、也不应该再手动导入一遍。
二、手动导入的工具包 —— 按需挑选，体积可控
在哪：发行包之外单独提供（例如仓库的 bin\工具包\ 目录），文件名不带版本号：ctfagent.<包名>.ctfpack。
怎么导入：打开「工具包」页面，点「导入 .ctfpack」，在文件选择框里按住 Ctrl 多选一次导入多个；单个体积很大的包（如 Ghidra 全套）建议用「从路径导入」，由 daemon 直接读盘更稳。
版本规则：同一个包名只保留最新版本，替换后文件名不变，重复导入不会累积旧版本。
导入后：建议点「全部启用」一次性打开包与其全部工具；已运行的任务不会热加载新包，需要新建任务。

适用范围与兼容性（重要）

本节说明每个工具包在什么环境下可以直接用、什么情况下需要额外条件。选包前请先对照。

通用前提（所有工具包）
操作系统：Windows x64。Linux / macOS 版本不随本包发布。
运行时：随应用分发的便携 Python 3.12（data/tools/windows/python）。沙箱 PATH 内可直接调用 python。
应用版本：BTF 2.9.x。工具包清单格式为 schemaVersion: 1，跨 2.9.x 小版本通用。
工作目录：任务工作区，写入权限限于 artifacts/**；读取限于 attachments/** 与 artifacts/**。
无外网时：除标注「网络」的工具外均可离线工作。
ctfagent.remote-vnc —— 需要目标开放 RFB/VNC 端口
适用：RFB 3.x（3.3 / 3.7 / 3.8），安全类型 None(1) 与 VNC Authentication(2)，编码 Raw(0)。
不适用：VeNCrypt(16/19)、TLS(18)、Apple/RA2(30/33) 等加密握手；需要双向 TLS 或证书的部署。
注意：VNC 口令在协议层最多使用前 8 字节；口令正确仍失败时优先怀疑位序处理，而不是密码错误。
ctfagent.qr —— 内置 zxing-cpp，无外部依赖
适用：QR Code 及 zxing 支持的一维/二维条码；PNG/JPEG 等常见位图。
实测能力：反色、90°/180°/270° 旋转、高斯模糊 r≤2 均可解；短边低于约 50 像素会失败，此时应放大裁剪图而不是换工具。
不适用：MaxiCode 等特殊符号（需 Java zxing）；严重透视畸变的照片建议先做透视校正。
ctfagent.media-ocr —— 内置 tesseract 与 chi_sim/eng 模型
版本：2.9.1.1 起改为 Python 入口（scripts/ocr.py）。2.9.1 及更早的 PowerShell 入口在 AppContainer 内存在路径解析问题，请升级。
适用：截图、扫描件、验证码类图片的中英文识别；支持相对与绝对路径。
不适用：手写体、严重倾斜、极低分辨率小字；此时先 screen-triage crop 放大 3~5 倍再识别。
ctfagent.net-probe / ctfagent.totp / ctfagent.screen
net-probe：仅做单次握手与单次 TCP 连接判断，不做字典爆破、不做端口段扫描；单目标请控制在低速率。
totp：纯本地计算，不发起网络请求；需要 Base32 种子。种子每个实例独立，不要复用上一台。
screen：纯本地图像处理；依赖 Pillow，无需网络。
版本号规则（2.9.1 起生效）
格式：<基线>.<日递增>.<当日构建号>
示例：2026-11-01 第一次打包 2.9.1.1；同日再打包 2.9.1.2；次日第一次打包 2.9.2.1。
发行包命名：CTF-BTFly-<版本号>-win64.zip，不再包含日期或「优化版」字样。

常见问题 FAQ

导入时提示“未受信任”/“未签名”，能用吗？

能。这些包是本地构建、没有商店签名，所以会走一次「确认安装未受信任 Tool Pack」的提示。确认后正常使用。

如果你是从别人那里拿到来源不明的 .ctfpack，不要安装——包内程序会在沙箱内以你的身份执行。

点击导入后一直转圈 / 进度不动，怎么办？

大包（尤其是逆向增强包）走浏览器上传容易卡。先改用「从本地路径导入」。

如果路径方式也卡住，多半是后台还挂着一个已结束任务的残留会话，占着工具包锁。解决方法：完全退出 BTFly 再启动，然后重试导入。

2.9.1 已改进 新版本会定期自动回收这类残留，但仍建议大包用路径导入。

导入成功，但 AI 说“没有 list-packs / elf-summary 这个工具”

工具包现在统一走 MCP。按顺序检查四步：

  1. 是否是旧任务？ MCP 绑定在创建任务时冻结，导入新包后必须新建一道题。
  2. 设置 → MCP 页里有没有 toolpacks（Tool Pack Bridge）且已启用。没有说明 daemon 没注册成功，可看 data\daemon.log 里有没有 tool pack MCP bridge registered。
  3. 版本行为：2.9.3.4 及以前必须重启应用；2.9.3.5 及以后最多等 30 秒自动生效。
  4. 若以上都对，看任务日志里的工具列表——只在 tools/call 失败时才可能是包本身损坏。
工具能被调用，但一直返回“文件不存在 / FileNotFoundError”

这是 2.9.3.6 之前版本的已知缺陷：MCP 工具的工作目录没有指向任务 workspace，相对路径（如 artifacts/a.png）全部找不到。

2.9.3.6 及以后已修复。升级后相对路径与绝对路径都能用。若仍遇到，检查路径是否写成了工作区之外的位置。

Ghidra（600 MB 以上）怎么导入？为什么点“导入”没反应？

大包必须用「从路径导入」：把 ctfagent.re-ghidra.ctfpack 放到本机任意目录，复制完整路径（如 D:\Downloads\ctfagent.re-ghidra.ctfpack）粘进输入框再点导入。

原因：为防止界面卡死，浏览器上传通道限制了 200 MB；超过上限会被拦下并提示改用路径导入。daemon 直接读盘不受此限制。

依赖提示：ctfagent.re-ghidra 本身无依赖，可单独使用；但 ctfagent.ctf-full-re（逆向全家桶）依赖 16 个包（含 re-ghidra），单独导入它会提示依赖缺失。

工具都在，但 AI 宁愿自己写 bash 也不用 packs__ 工具

这是模型的工具选择偏好，不是链路故障。可以这样引导：

  1. 在题目描述里明确写「优先使用 packs__ 开头的工具，不要用 bash 拼命令行」；
  2. 把具体场景写死，例如「看图/识图必须调用 packs__ctfagent_media_ocr_ocr」；
  3. 如果仍然绕过，说明该包的 description 不够清楚，可以在包定义里补一句适用场景。
为什么工具名都带 packs__ 前缀，很长很难记？

前缀用于区分「哪个工具包提供的同名工具」，避免冲突。你不需要记：在题目描述里说清楚目标，AI 会从工具列表里自己挑。

“完全离线”模式下，题都没开始就报模型请求失败

这是预期的：完全离线会阻断一切外网访问，而 AI 的模型请求也要走网络，所以模型用不了。

需要 AI 参与的题目请选默认的「公网与局域网」；只有纯本地分析、不需要模型时才用离线。

提示“沙箱不可用 / required capability ACE is missing”

这是 Windows 沙箱目录权限被重置导致的。解决顺序：

  1. 设置里点一次「重试准备」（或重启应用，让它在启动时重新准备）。
  2. 仍失败再看磁盘权限是否被安全软件改过。

不要为了绕过它去选「仅本次改用宿主执行」——那会失去沙箱隔离。

逆向增强包很大，每次开题都变慢，能只装基础包吗？

可以。基础包已覆盖大部分场景；只有需要 Ghidra 伪代码时才用增强包。系统会按题目类型自动选择——非逆向题不会加载增强包。

AI 明明找到了 flag，但显示“未验证”

“已验证”表示 AI 用程序真的验证过（例如解密后目标串匹配、校验函数返回 True）。如果它只是从文件里读到一个像 flag 的字符串，就会标为未验证。

你可以人工确认后手动通过。若确认无误却一直显示未验证，检查 artifacts/final-result.json 是否写成了标准结构：

工具包占多少磁盘？能卸载吗？

基础包约 100 MB，逆向增强包约 1 GB（含 Ghidra 与 JDK）。可以在工具包页面「卸载」，被运行中任务引用的版本会拒绝卸载，等任务结束再删。

升级到 2.9.1 后，旧版本工具包还能用吗？

工具包版本跟随主程序，2.9.1 的包请配套使用。旧版本可以保留（同 ID 多版本共存），但建议停用旧版避免混淆。

版本与更新

  • 本文档由打包流程按实际产物自动生成工具清单，以页首「本发行版适用的工具包清单」为准。
  • 工具包文件名不带版本号：统一为 ctfagent.<包名>.ctfpack；版本只存在于包内 manifest.json。
  • 同一个包名只保留最新版本；被取代的旧版本会被自动归档，不会在目录里累积。
  • 更新方式：直接用新文件覆盖导入即可（同名替换），无需先卸载。
  • 回滚方式：导入上一版本的归档文件；已运行任务仍使用其各自冻结的版本。
